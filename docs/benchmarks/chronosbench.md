# ChronosBench Workload Suite

> **Status: planned, not implemented.** ChronosBench is the future reproducible workload suite. It must emit the complete [benchmark manifest](benchmark-contract.md) and validate results before reporting speed.

## Dataset profiles

Both profiles use the canonical [trades, quotes, metrics, and structured-event schemas](../product/data-model.md#canonical-proposed-schemas), deterministic generators, and explicit cardinality/skew/lateness parameters.

- **Local development profile:** 250,000 trades, 1,000,000 quotes, 1,000,000 metric samples, and 100,000 structured events; 1,000 market symbols, 25,000 metric series, and 100 services. It is sized for rapid correctness and profiling loops, not publication of production claims.
- **Reference profile:** 100,000,000 trades, 1,000,000,000 quotes, 1,000,000,000 metric samples, and 100,000,000 structured events; at least 25,000 market symbols, 10,000,000 metric series, and 10,000 services with declared Zipf/hot-key parameters. These are generated dataset targets, not achieved capacity or performance results.

Every scenario can apply a declared scale factor. A comparison is valid only when both systems/runs use byte-identical generated logical inputs or a verified equivalent export.

## Scenarios

Abbreviations in the table: latency includes the operation-specific distribution; resources include CPU, RSS, disk, and network from the [publication contract](benchmark-contract.md).

| # | Scenario | Dataset and operation mix | Correctness checks | Measured metrics | Variables to sweep | Invalid comparisons |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Bulk columnar ingestion | Fresh tables; large ordered batches, ingest only, flush policy declared. | Input identities/counts, values, partition/part checksums, full sampled scans. | Rows/bytes per second, batch latency, CPU/RSS, disk bytes, compression/amplification. | Batch rows/bytes, width, symbols/series, codec, head/flush thresholds. | Comparing different schemas, codecs, validation, or prebuilt parts with accepted ingest. |
| 2 | Durable group-committed ingestion | Concurrent producers using `LOCAL_SYNC`; future `QUORUM_SYNC` is separate. | Acknowledgment/recovery identity reconciliation; zero covered-mode loss. | Ack p50–p99.9, throughput, sync count/time, group size, disk/network, loss count. | Clients, batch size, group delay/limit, storage, mode. | Presenting `ASYNC` as durable or comparing per-event sync with larger batches without disclosure. |
| 3 | Mixed ingestion and historical queries | Continuous ingest plus fixed short/long SELECT mix over retained data. | Query hashes/reference results at captured snapshots; all accepted rows recoverable by mode. | Ingest/query tails, throughput, freshness, CPU/RSS/I/O, interference. | Query concurrency/mix, ingest rate, cache state, flush/compaction. | Running queries only after ingest or comparing different snapshot semantics. |
| 4 | Hot recent-window aggregation | Recent trades/metrics; one-second/minute grouped count/sum/VWAP. | Scalar/reference recomputation including late rows. | Update/query latency, rows/s, state bytes, CPU, freshness lag. | Window width, groups, skew, lateness, subscriber/query count. | Omitting correction work or comparing pre-aggregated input with raw input. |

| 6 | Selective symbol/time scan | Narrow symbol/venue/series predicates over bounded time ranges. | Exact identity set and values versus oracle; pruning cannot drop matches. | Latency, rows/pages/bytes scanned, pruning ratio, CPU/I/O. | Selectivity, key skew, time range, part overlap, index configuration. | Different predicate selectivity or optional index without labeling. |
| 7 | ASOF join | Trades left, quotes right, canonical event ordering. | Row-by-row match against scalar ASOF oracle including ties and no-match cases. | Join latency/throughput, CPU/RSS, bytes decoded, morsel skew. | Symbols, quote/trade ratio, lateness, time ties, projection, parallelism. | Different tie-breaking, tolerance, or prejoined data. |
| 8 | High-cardinality observability query | Metrics/events grouped and filtered by tenant, metric/service, host/region. | Exact groups/counts and numeric tolerance against scalar oracle. | Latency, throughput, state/RSS, CPU, pruning/I/O, spill. | Active series, label-column cardinality, skew, time range, memory limit. | Lower cardinality, unbounded memory, or approximate distinct substituted for exact work. |
| 9 | Live subscription fan-out | One committed source stream delivered to many identical and varied subscriptions. | Per-subscriber gap/sequence/result reconciliation with source log. | Delivery p50–p99.9, ingest impact, fan-out throughput, RSS/network, lag. | Subscribers, query diversity, event rate, window state, reconnects. | Dropping slow clients/results without counting or disabling snapshot phase. |
| 10 | Slow-subscriber backpressure | Subscribers consume at controlled rates below production. | No ingestion deadlock; explicit overflow; valid resume suffix or expiry error. | Memory bounds, disconnect/overflow time, ingest tails, retained bytes, resume latency. | Buffer limit, consumer rate, subscribers, retention, overflow policy. | Unbounded buffers, hidden loss, or shorter run than buffer-fill time. |
| 11 | Out-of-order ingestion | Declared delay distribution spans in-order, reorder horizon, and delta path. | Current/system-time rows and windows match event/version oracle. | Ingest latency, delta bytes, query cost, compaction/amplification, correction latency. | Delay distribution, horizon, watermark, batch order, skew. | Different lateness distributions or discarding late data. |
| 12 | Duplicate retransmission | Controlled duplicate batches and rows within/across dedup horizon. | One logical input per protected identity; expected horizon-expired outcomes. | Retry latency, dedup throughput/state bytes, CPU/I/O. | Duplicate rate, horizon, restart points, client count, payload size. | Counting duplicates as useful throughput or assuming infinite retention. |
| 13 | Corrections and tombstones | Multi-version identities, event-time changes, replacements, deletions. | Current and every sampled system-time view match bitemporal oracle. | Mutation/live correction latency, storage/space amplification, compaction cost. | Version depth, correction/tombstone rate, history retention, window crossing. | Latest-only datasets or dropping retained versions. |
| 14 | Flush under load | Sustained ingest while heads seal and CSEG parts install. | Snapshot counts/hashes before/during/after; recovery at injected boundaries in correctness runs. | Foreground tails, flush throughput/duration, sync/I/O, temporary space. | Head threshold, concurrent flushes, codec, storage, ingest rate. | Disabling flush, excluding foreground tails, or different durability. |
| 15 | Compaction under load | Overlapping base/delta parts compact during ingest and queries. | Pre/post logical equivalence at retained snapshots; no premature reclaim. | Foreground tails, compaction throughput/debt, CPU/I/O, read/write/space amplification. | Part overlap, delta ratio, workers, throttle, history depth. | Starting with already compacted data or ignoring compaction resource use. |
| 16 | Restart recovery | Controlled clean/unclean stops at declared WAL/manifest states. | Recovered identities/results versus acknowledged set and mode; repeat recovery identical. | Unavailable/recovery time, bytes/records replayed, CPU/I/O, loss count. | WAL size, checkpoint age, parts, shutdown point, mode, cache. | Clean restart labeled crash recovery or ignoring lost `ASYNC` acknowledgments. |
| 17 | Future leader failover | Replicated reference workload; kill/isolate leader during writes/reads. | Raft history/linearizability check; no uncommitted visibility; mode-appropriate loss. | Failover/unavailability, ack/read tails, catch-up bytes, errors/retries. | Replicas, fault type, load, consistency/durability mode, network delay. | Single-node results, different fault models, or eventual reads labeled linearizable. |
| 18 | Future tablet movement | Add/catch-up/remove replicas while workload continues. | Complete data, valid membership order, snapshot/resume continuity, query oracle. | Movement time/bytes, foreground tails, temporary space, catch-up, errors. | Tablet size/count, bandwidth cap, load/skew, concurrent moves. | Remove-before-add, idle-only movement, or omitted temporary resources. |

## Execution and publication

Scenarios 17–18 remain unavailable until distributed phases pass. Each run stores generated input identity summaries, expected-result artifacts, raw measurements, and failure/retry logs. A scenario is invalid if its correctness checks fail, required metadata is absent, or it compares unequal durability/consistency contracts. ChronosBench will not embed target throughput or latency as though achieved.
